## 1. 先想清楚一个问题：为什么我没有从 PID 开始？

我最开始了解 RoboMaster（RM）的时候，翻开任何一支战队的开源代码、看任何一集电控入门视频，满屏都是 PID。

我先去看 PID 的视频。看了大概 40 分钟，我卡在一个很具体的地方：**不知道 Kp 到底乘在哪个量上。**

后来把这件事想明白了：PID 的一条式子

```text
输出 = Kp · e + Ki · ∫e dt + Kd · de/dt
```

里，`输出` 在电机上通常是**脉宽调制（Pulse Width Modulation, PWM）的占空比**或电流环的给定，`e` 是**编码器读数与目标值之差**，而 `dt` 是**定时中断的采样周期**。

这三样东西——产生 PWM、读编码器、定周期中断——全是 STM32 外设的事。我一个都不会做的时候，PID 对我来说就只是一条数学式子，没有任何可以下手的地方。

再往下想，还有两个更硬的理由：

| 我想做的事 | 需要的前置能力 | 缺了会怎样 |
|---|---|---|
| 调 PID 参数 | 把波形从串口发到电脑上看 | 没有曲线，调参就是盲猜：改大改小只能靠「感觉变好了」 |
| 接 OLED 看数据 | I2C 上拉电阻、供电、共地 | 屏不亮时，分不清是代码错还是线接错，只能两边瞎试 |
| 焊/搭电路 | 限流电阻怎么算、电流多大 | LED 或引脚烧掉，然后误以为是芯片坏了 |

所以我的顺序是：

1. **电路基础**——让我知道电为什么会烧东西、信号为什么上不去。这一步不学，后面每次失败都要在「软件错」和「硬件错」之间猜。
2. **STM32 外设**——让我能产生信号（PWM）、读信号（ADC/串口/编码器）、显示信号（OLED），也就是**先拿到观测手段**。
3. **控制算法**——有输入有输出有观测之后，PID 才是一门可以调、可以验证的手艺，而不是背公式。

一句话：**不是 PID 难，是它需要的一切都在它前面。**

## 2. 原理：这条路线是按「依赖关系」排的，不是按难度排的

每一层都在为上一层提供必要的东西，箭头是「没有它就做不了下一层」：

```text
        ┌──────────────────────────────────────────────────────────┐
 第 0 层 │ C 语言：变量 / 指针 / 结构体 / 位运算 / 看编译报错        │  已有一点点
 (工具)  │ + Git：知道怎么把每次改动存下来                          │
        └───────────────────────────┬──────────────────────────────┘
                                    │
        ┌───────────────────────────▼──────────────────────────────┐
 第 1 层 │ 电路基础：欧姆定律 / 分压 / 限流 / 上拉下拉 / 去耦        │  第 2、8 周
(看懂硬件)│ 产出：能算出 LED 串 330 Ω 时电流多大、为什么电源脚要加 100 nF│
        └───────────────────────────┬──────────────────────────────┘
                                    │ 「电路不冒烟，才有心情调代码」
        ┌───────────────────────────▼──────────────────────────────┐
 第 2 层 │ STM32 外设：GPIO → 定时器/PWM → 串口 → I2C/OLED → ADC    │  第 1、3~7 周
(让芯片动)│ 产出：能产生信号、能读信号、能把数据发到电脑上看          │
        └───────────────────────────┬──────────────────────────────┘
                                    │ 「有输出、有观测，才有闭环可言」
        ┌───────────────────────────▼──────────────────────────────┐
 第 3 层 │ 控制算法：PID 原理 → PC 仿真 → 串口调参 → 单闭环          │  第 9~11 周
(让它听话)│ 产出：能讲清每个参数改变曲线的哪一段                     │
        └───────────────────────────┬──────────────────────────────┘
                                    │
        ┌───────────────────────────▼──────────────────────────────┐
 第 4 层 │ 战队级：CAN 总线 / M3508 等电机 / 底盘功率控制 / PCB 打样 │  第 13 周起
(上车)  │ （12 周表里没有这几项，原因见第 5 节，我不假装会）        │
        └──────────────────────────────────────────────────────────┘
```

### 2.1 每个外设对应车队里的什么东西

| 定时器 / PWM | 电机调速、舵机角度、蜂鸣器音调 | [04](04-定时器与PWM.md) |

| I2C | 0.96" OLED、部分惯性测量单元（Inertial Measurement Unit, IMU） | [06](06-I2C与OLED.md) |
| 模数转换器（Analog-to-Digital Converter, ADC） | 电位器、电池电压监测、电流采样（超级电容、功率控制的基础） | [07](07-ADC采样.md) |

### 2.2 为什么 CAN 不在前 12 周

RM 的电机基本都挂在 CAN 总线上，但我把 CAN 放在第 12 周之后，理由有两条：

1. CAN 本身不复杂，**难的是它服务的那套东西**——电流环、编码器反馈、功率限制。在没做过单闭环之前上 CAN，只是从「不会调 PID」变成「不会调 PID 且多了 4 个电机在转」。
2. 我手上只有 F103C8T6 最小系统板，**没有电机、没有 CAN 收发器**。Wokwi 的 STM32F103C8 仿真里 **CAN 也未实现**（见 [Wokwi 官方部件页](https://docs.wokwi.com/parts/board-stm32-bluepill)），也就是说这块短期内没法上机验证。写进 12 周计划里就是一条「永远打不上勾」的任务。

所以我的写法是：**明写在第 4 层，不塞进 12 周表**。面试被问到时我会直接说「CAN 我还没写过，这是硬件到手后的第一件事」。

## 5. 逐段解释：这张表里几个刻意的安排

**为什么第 3 周才讲中断，不放在第 1 周？**
因为中断是一个「代码看不出问题、现象却不对」的东西。先把 GPIO 轮询写熟，我才有一个对照物：同样是读按键，轮询是在 `while(1)` 里不停看，中断是让硬件在看。有了这个对照，再讲 NVIC 的优先级分组才有意义。

**为什么第 4 周把定时器和 PWM 放在一起？**
它俩是同一个外设的两副面孔：定时器到点了叫一声（更新中断），PWM 是定时器一直在比较、把比较结果输出到引脚。分开讲会变成两个知识点；一起讲只需要理解一次「计数 → 比较 → 输出」。

**为什么电路基础插在第 2 周和第 8 周，而不是集中一次讲完？**
因为电路知识的价值和当周要接的东西绑在一起：第 2 周要接 LED，就讲限流电阻；第 8 周要画板子，就讲去耦和电源。集中讲一遍「模电」对我是没用的——不接线的时候，我记不住为什么要加电容。

**为什么第 9 周和第 10 周要拆开？**
第 9 周在电脑上跑仿真，好处是我可以**随便改参数、反复重跑**，不用担心把板子搞坏。等我在仿真里把「Kp 变大 → 上升变快但超调变大」这件事看出来，第 10 周上机时我就知道自己在找什么。反过来先上机，我会陷入「车在抖，不知道是哪个参数」的状态。

**为什么第 12 周不排新知识？**
因为综合那一周的价值不在学新东西，而在**用旧东西串出一样能交付的成品**，以及诚实地复盘。RM 面试里「你做过什么」比「你学过什么」重要得多。

## 6. 我踩的坑

这一章还没上机，所以这里写的不是实验的坑，而是**我在排计划时踩的坑**——同样是坑，而且我觉得比接线错误更值得先记下来。等板子到手，各章会写各自的实物坑。

### 6.1 坑一：先去看 PID

**现象**：看 RM 相关视频，前 20 分钟就在讲 PID，我以为那是入门内容，直接去找 PID 教程看。看到第 40 分钟放弃了。

**原因**：我误把「出镜率高」当成了「入门内容」。PID 在视频里出现得多，是因为它是**结果**——每支队伍的成果都用它描述，而不是因为它是学习的起点。视频里不会花时间讲「PWM 占空比是怎么被写进寄存器的」，因为对讲的人那已经是常识了。

**怎么定位出来的**：我自己问了一句「如果现在给我一块板子，让我把 Kp 调大一点，我该去改哪一行代码？」——我答不上来，说明我缺的不是 PID 知识，是它下面那一层。

**怎么改的**：把 PID 挪到第 9 周，并且**先用 PC 仿真**理解参数，再上机。

### 6.2 坑二：一开始想学 F407，还想在 HAL 库和标准库之间挑一个

**现象**：F103 是最便宜、资料最多的，但 RM 的车基本用 F407。我担心学 F103「白学」，在选型上纠结了好几天；接着又纠结是学 HAL 库还是「标准库」（StdPeriph）。

**原因**：我把「学得对不对」和「学得贵不贵」搞混了。F103 和 F407 的**编程模型**是一样的：时钟树要靠 RCC 配、GPIO 要靠 CRL/CRH 或寄存器配、定时器都是「预分频 + 自动重装 + 比较」这一套。HAL 的函数名在 F1 和 F4 上几乎一样（`HAL_GPIO_Init`、`HAL_TIM_PWM_Start`），换芯片主要是改 `MX_xxx_Init()` 里的参数和引脚，不是重学。

**怎么改的**：
- 先买 F103C8T6（¥15 级别），把外设模型学明白；
- 库只选 **HAL 库**，因为 STM32CubeMX 生成的代码就是 HAL，而海报里明确要求「会使用 STM32CubeMX 配置并完成简单项目」——选 HAL 和招新要求是同一条线，不额外花时间。

这条判断的对错我暂时没法用数据证明，只能等我换到 F407 时回来验证，先如实写在这儿。

### 6.3 坑三：第一版计划排得太满

**现象**：第一版计划是「每天 2 小时，一周学 3 个外设」。写到第 1 周就执行不下去——环境搭建本身就吃掉了一个晚上（装 CubeMX、装器件支持包、装驱动、第一次烧录失败）。

**原因**：我在排计划时把「看视频的时间」当成了「学会的时间」。视频里别人敲 10 行代码就点灯，是因为他环境早就配好了；我配环境时踩的坑是视频里没有的。

**怎么改的**：改成**每周只有一条产出物**，并且前两周故意排得松（第 1 周只点灯，第 2 周才算限流电阻）。排计划时把「环境、驱动、报错」这类不可见的成本算进去，否则计划一定会崩，崩了之后就会开始怀疑自己不适合学这个。

   ```text
   stm32-learning-notes/
   ├── README.md
   ├── docs/          # 每章一个 md，命名 0N-主题.md
   ├── code/          # 每章的 Keil 工程，命名 0N-主题，含 .ioc 文件
   ├── assets/        # 图片、SVG 曲线
   └── wokwi/         # 没硬件时的仿真工程
   ```
2. **把第 4 节那张表原样抄进你的 `docs/00-学习路线图.md`**，然后把「周次」改成你的实际日期（比如「第 1 周」→「2026-09-07 那一周」）。写日期比写序号有用：序号不会提醒你落后了。
3. **每周只允许自己开一条产出物**。开工前先在 `code/` 下建好这一周的工程目录，做完就往里提交。
4. **每周结束时填表**，只允许填三种状态：`✅ 达到`、`🔬 未验证`、`❌ 没做到（原因）`。不允许空着——空着就等于没做。
5. **检验标准要用「讲出来」的方式自测**：把表里那句话当成面试题，对着空气讲 60 秒。讲不顺的地方就是没懂的地方，回去补。
6. **没做到的那一周，把原因写在表下面**，不要偷偷把标准降低。招新面试时，能说清「我在中断优先级上卡了两周，最后靠 RM0008 第 9 章弄明白了」比一张全绿的假表有说服力。
7. **硬件没到之前，用 [Wokwi](https://wokwi.com/) 先跑逻辑**（工程放 `wokwi/`）。⚠️ 但要记住它的边界：STM32F103C8 仿真里 GPIO / USART / I2C / SPI / TIM1-4 / EXTI 都支持，**ADC 只有 ADC1 的基础转换**，而 **CAN / DMA / RTC / IWDG / PWR 没有实现**。所以仿真能验证「逻辑对不对」，不能验证「电路对不对」，更不能替代真机。

## 8. 自测题（面试可能这么问）

**Q1：为什么先学串口，再学 PID？**
A：因为 PID 调参需要看曲线。参数改对了还是改错了，只有在波形上才看得出来。串口是把单片机内部的数据搬到电脑上的最便宜的通道（一根 USB-TTL，¥5 级别），没有它，调参只能靠「感觉好像好一点了」，那不是工程做法。

**Q2：如果用一句话说清「电路基础 / STM32 外设 / 控制算法」三者的依赖关系，你怎么说？**
A：电路基础保证东西不烧、信号能被正确传出去；STM32 外设提供产生信号和观测信号的手段；控制算法是在这些手段之上，让输出按我期望的方式变化。后一层缺了前一层，就只能靠猜。

**Q3：时钟树里的 72 MHz 是「芯片的速度」吗？**
A：不是「芯片跑多快」这么简单。72 MHz 是系统时钟（SYSCLK），它决定了 CPU 和挂在 AHB 上的总线的节奏；但外设还有各自的限制——APB1 上的外设最高 36 MHz，所以要分频 /2；APB2 上的可以到 72 MHz。另外定时器在 APB 预分频不为 1 时，时钟会被硬件自动 ×2，所以挂在 APB1 的 TIM2 实际还是 72 MHz。这些数都要按 RM0008 第 7 章的时钟树算，不能想当然。

**Q4：12 周表里没有 CAN，可 RM 的电机全走 CAN，你怎么解释？**
A：因为我还没有 CAN 收发器和电机，Wokwi 的 STM32F103C8 仿真也没有实现 CAN，写进 12 周就是一条永远打不上勾的任务。我把它放在第 13 周起，并明确写成「还没接触」——比写在计划里假装会了要诚实，也更容易被追问。

**Q5：检验标准为什么写成「能说清 NVIC 优先级分组怎么设」，而不是「学会中断」？**
A：「学会中断」没法验证，我自己说学会了，也没人能反驳。而「能说清优先级分组怎么设」是一句话就能测的：说不出来就是没学会，没有中间状态。计划里的每一条检验标准我都要求自己能用嘴答出来，答不出来就当没完成。

## 10. 我怎么用这些资源

资源不是越多越好。我给自己定的用法是：

**1）视频看三遍，三遍的目的完全不同。**

- 第一遍：**不暂停，1.5 倍速看完**。目的只有一个——知道这一节在解决什么问题，允许自己有听不懂的地方。新手最容易犯的错是第一遍就逐句抠，一集 40 分钟的视频能耗掉 3 小时，然后放弃。
- 第二遍：**暂停跟敲，一行一行自己打**，不复制粘贴。复制过来的代码不会报错，也就不会暴露「我以为我懂了」的地方。
- 第三遍：**关掉视频，只看我自己的笔记复现一遍**。卡住的地方就是真没懂的地方，回去定位到视频的具体几分钟再看。

**2）每看完一小节，合上视频写三行。**

```text
这节解决的问题：______
关键的东西（寄存器名 / HAL 函数名 / 参数）：______
我还不懂的一个点：______
```

第三行写不出来，说明我在「跟着敲」阶段其实是抄的。

**3）手册不是用来从头读的，是用来搜的。**

RM0008 有 1000 多页，从头读是自欺欺人。我的做法是**代码里出现什么名字就去搜什么名字**：`HAL_GPIO_Init()` 里有 `CRL`/`CRH`，就翻第 9 章的端口配置表；`SystemClock_Config()` 里有 `PLLMUL`、`PPRE1`，就翻第 7 章 RCC。搜到之后，把那一节的结论抄进当章的「手册依据」，标上章节号。

**4）搜报错用「原文 + 英文关键词」。**

- 第一步：把 Keil / CubeMX 的**报错原文整句**复制去搜，不要自己转述。
- 第二步：中文搜不到结果，就把关键词换成英文。例：`no target connected stlink`、`core_cm3.h not found keil`、`stm32cubemx serial wire disabled locked`。同一个问题英文的答案通常多一个数量级。
- 第三步：加限定词收窄，`site:community.st.com`、`site:bbs.robomaster.com`。
- 第四步：**搜到的结论必须回手册验证**。论坛上「这样改就好了」很多是碰巧，照抄会埋雷。

**5）资源分层，不混着用。**

- 江协科技 = 主线，按顺序推进，不跳集；
- 中科大 / SUES 培训 = 换个讲法的查漏工具，只在某一块没懂时看；
- RM 官方社区 = 只在问「战队到底怎么干」的时候看；
- RM0008 / 数据手册 = 裁判。

**6）时间上按周结算，不按天。** 我按每周 6~8 小时排（工作日 2 个晚上各 1.5 h + 周末半天）。按天排会失败，因为板子/驱动/报错这些不可见的成本不均匀地分布在各天。

**7）笔记和代码一起提交。** 每章一个 md，代码随工程提交，坑单独一节写「现象 / 原因 / 我怎么定位出来的 / 解法」四段。写不出「怎么定位出来的」，说明我是蒙对的，下次还会错。

## 11. 卡住的时候怎么办

卡住是常态。我给自己定的规矩是：**在一个问题上连续卡超过 30 分钟，就先把现象记到笔记里，做别的或者收工，第二天再看。** 疲劳状态下继续试，做的大多是重复的无效尝试，还会把「尝试记录」搞乱。

### 11.1 先分类，再求助

不同阶段的卡，看的地方完全不同，先判断卡在哪一类：

| 阶段 | 典型现象 | 先查什么 |
|---|---|---|
| 编译期 | Keil 报红字，Build 失败 | **只看第一条报错**。后面几十条常常是第一条引起的；缺头文件多半是器件支持包或路径问题 |
| 烧录期 | "No target connected"、"Cannot access target"、连不上 | 接线（SWDIO/SWCLK/GND 有没有接错、有没有共地）→ 供电 → SWD 时钟降速 → 是不是被自己写的代码占用了 SWD 引脚 |
| 运行期 | 烧进去了但没反应 | 先回到最小验证：能不能点灯？时钟对不对？外设时钟有没有使能？ |
| 现象期 | 能跑，但数据不对（乱码、读数跳、波形怪） | 单位、量程、采样周期、参考电压——按数量级先估一遍，`3.3 V / 4096` 这类式子先算出来再怀疑代码 |

### 11.2 求助路径

| 渠道 | 适合问什么 | 注意 |
|---|---|---|
| ST 官方社区 https://community.st.com/ | CubeMX、HAL 库、工具链的具体报错 | 用英文问，标题写清芯片型号 + 工具版本 |
| RoboMaster 官方社区 https://bbs.robomaster.com/ | CAN 电机、整车架构、功率控制这类战队级问题 | **先搜再发**，重复贴没人理 |
| B 站评论区 / UP 私信 | 教程里某一步和你的界面对不上 | 带视频时间点 + 自己的界面截图，比「up 我这步不对」有效得多 |
| 战队师兄 / 招新群 | 搜不到的惯例、往届踩过的坑 | 直接问，别因为「怕显得菜」而自己耗一周 |
| 卖家客服 | 山寨 ST-Link、开发板出厂问题、器件型号对不对 | 只对「东西本身」有效，对代码问题无效 |
| 搜索引擎 / 大模型 | 快速定位方向、给出可能的原因列表 | **只能用来定位方向**，结论必须回 RM0008 或数据手册验证 |

### 11.3 提问前必须准备的四样东西

我要求自己在发问之前把这四样写出来，写不齐就先别发——因为写的过程本身经常就把问题解决了。

1. **最小可复现代码**。不是把整个工程压缩包发出去，而是「能复现这个问题的最少代码」。比如：只有 `main.c` + `main.h` + `.ioc`，删掉所有跟问题无关的外设。多数时候，删代码的过程中问题就露出来了。
2. **现象描述，带原文**。报错**整段原样粘贴**，不要只贴最后一行、也不要自己转述。要说清是编译期还是烧录期还是运行期；开发板上的表现（LED 全灭？闪一下？）也写上。
3. **已经排查过的项**。「我试过 A，结果 B；我试过 C，结果 D；因此我排除了 E」。这一条最能换来认真回答——它说明你不是来要答案的，是来对答案的。
4. **环境和硬件信息**。芯片型号（STM32F103C8T6）、STM32CubeMX 版本、Keil MDK 版本、ST-Link 是原装还是山寨、接线方式（哪个脚接哪个脚）、供电方式（USB 还是 ST-Link 的 3.3 V）。

**一个反面例子**：

> 「为什么我的 LED 不亮？」

这句话没法回答，因为可能的原因至少有几十个：没使能 GPIO 时钟、极性写反、限流电阻太大、杜邦线断了、SWD 下载的是旧程序、芯片被锁死根本没烧进去……提问时必须把范围缩到别人一句话能回答的程度。

**一个正面例子**（我会这样写）：

> 芯片 STM32F103C8T6，CubeMX 6.x，Keil MDK 5.x，ST-Link V2（山寨）。
> 现象：Keil 点 Download 提示 `No target connected`；但换一根杜邦线、把 ST-Link 的 SWCLK 从 4 MHz 降到 1 MHz 后，有时能连上。
> 已排查：板子 USB 供电正常（板载电源灯亮）；SWDIO→PA13、SWCLK→PA14、GND→GND 三点接线用万用表通过断；换过一根杜邦线现象不变。
> 我的猜测：是 ST-Link 的线太长/接触不良，还是 SWD 引脚被程序占用了？

这样的问题，别人扫一眼就能给出方向。
